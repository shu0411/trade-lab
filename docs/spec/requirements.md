# Trade Lab 詳細仕様

コンセプトは [concept.md](./concept.md) を参照。本ドキュメントは初期リリースの機能要件・画面構成・非機能要件・技術スタック・将来拡張をまとめたもの。

---

## 1. 基本的な利用の流れ

### 1.1 仮説を記録する

対象銘柄について以下を記録する。

* 日付、銘柄コード、銘柄名
* チャートパターン、判断根拠、補足メモ、チャート画像
* エントリーまたは見送り

エントリーの場合はさらに、エントリー価格・利確目標・損切目標・保有予定日数を記録する。

### 1.2 経過を確認する

記録は結果が確定するまでオープン状態として管理し、一覧・詳細画面から未検証の仮説を確認できる。

### 1.3 結果を記録する

検証期間の終了後、終了価格・最大含み益・最大含み損・成功/失敗/引き分けの判定・振り返りメモを入力する。保存するとクローズ状態になる。

### 1.4 分析する

蓄積した結果から、全体成功率、パターン別・判断根拠別成功率、オープン/クローズ件数、最近の記録を確認する。

## 2. 機能要件

### 2.1 仮説記録

* 記録タイプ: エントリー / 見送り
* 共通入力: 日付、銘柄コード、銘柄名、チャートパターン、判断根拠（複数選択可）、補足メモ、チャート画像
* エントリー時の追加入力: エントリー価格・利確目標率・損切目標率（必須）、保有予定日数（営業日、任意）
* エントリー価格・利確目標率・損切目標率から利確目標価格・損切目標価格を自動計算
* 初期の固定選択肢
  * チャートパターン: 押し目 / ブレイクアウト / その他
  * 判断根拠: 25日線反発 / 75日線反発 / 高値更新 / 出来高増加 / ゴールデンクロス / 安値切り上げ / 移動平均線上向き
  * 固定選択肢にない内容は補足メモに記録する

### 2.2 仮説一覧

* 表示項目: 日付、銘柄コード、銘柄名、記録タイプ、チャートパターン、ステータス、結果
* 新着順に表示
* 記録タイプ（すべて/エントリー/見送り）、ステータス（すべて/オープン/クローズ）で絞り込み可能

### 2.3 仮説詳細

* 登録内容・チャート画像を表示
* オープン状態のエントリーは結果を入力可能
* 記録は削除可能（要確認ダイアログ、復元機能は対象外）

### 2.4 結果記録

* 入力項目: 終了価格・結果区分（成功/失敗/引き分け）は必須、最大含み益率・最大含み損率・振り返りメモは任意
* 終了価格とエントリー価格の比較による自動判定を参考表示するが、最終判定はユーザーが選択する
* 登録後、ステータスをクローズに変更し、クローズ日時を記録

### 2.5 ダッシュボード

エントリー総数、オープン/クローズ件数、全体成功率、パターン別成功率、最近のエントリー記録（最新5件）を表示する。見送り件数は集計対象として保持するが、表示方法は今後検討。

### 2.6 分析

クローズ済みのエントリー記録を対象に、パターン別・判断根拠別に記録数、クローズ件数、成功件数、成功率を集計する。

* 成功率 = 成功件数 ÷ クローズ済み件数 × 100（オープン中は分母に含めない）
* 1件に複数の判断根拠がある場合、それぞれの集計対象に含める
* 見送り記録は初期フェーズでは分析対象外

### 2.7 チャート画像

任意で添付可能。判断時点の状況確認用。画像はS3に保存し、一般公開はせず、アップロード・閲覧とも期限付き署名URL経由でのみアクセスする。

### 2.8 記録削除

確認の上で削除可能。復元機能は初期フェーズでは対象外。

## 3. 業務ルール・データルール

* **ステータス**: オープン（結果未登録）/ クローズ（結果登録済み）。新規登録時はどちらもオープン。エントリーは結果登録でクローズに変わる。見送りのクローズ方法は今後検討。
* **エントリーと見送り**: エントリーは価格目標・結果を管理し、見送りは判断時点の情報のみ保存する。初期フェーズでは見送り後の値動き・成否は分析しない。
* **数値**: 価格は円単位、目標率・含み益損率はパーセント。目標価格は整数に丸め、損切目標率は絶対値を下落率として扱う。
* **日付**: 仮説の日付はユーザーが判断を行った日。作成日時はシステムが別途保持する。

## 4. 画面構成

* ダッシュボード: 全体状況・成功率・最近の記録
* 仮説一覧: タイプ/ステータスで絞り込み
* 仮説登録: エントリー/見送りの新規登録
* 仮説詳細: 登録内容・画像・結果、オープン中は結果入力フォーム
* 分析: パターン別・判断根拠別成功率のグラフ

## 5. 初期リリースの対象範囲

### 対象

エントリー/見送り記録、チャートパターン・判断根拠の選択（複数選択・自由メモ含む）、チャート画像添付、利確・損切価格の自動計算、仮説一覧（絞り込み含む）、仮説詳細、結果入力、記録削除、ダッシュボード、パターン別・判断根拠別成功率。

### 対象外

証券会社連携、実売買執行、資産管理、損益・税金計算、リアルタイム/過去株価の自動取得、チャート自動生成、銘柄名自動補完、AIによる売買判断・チャート分析・投資助言、複数ユーザー対応・データ共有・SNS機能・ランキング・通知、見送りの成否分析、仮説の編集、削除データの復元、高度な統計分析、バックテスト、資金管理、ポジションサイズ計算。

## 6. 非機能要件

* **利用環境**: PCのWebブラウザを主対象。スマートフォンでの閲覧・入力ができることが望ましいが優先度は低い。
* **性能**: 個人利用で数百〜数千件の記録を想定。一覧・詳細・登録・分析は待ち時間を感じない範囲で完了すること。
* **可用性**: 高可用性構成は必須ではないが、クラウド上で継続利用できることを前提とする。
* **セキュリティ**: チャート画像は非公開、データ保存先への直接アクセスは不可、通信はHTTPS、アプリケーションは必要範囲のみアクセス。将来の複数ユーザー対応を見据え認証・認可を追加可能な構成にする（初期フェーズでは認証は未実装のため公開範囲は運用上の検討事項）。
* **データ保持**: ユーザーが明示的に削除しない限り保持し、再デプロイ等で意図せず失われないこと。
* **保守性**: フロントエンド・バックエンド・インフラを分離し、チャートパターンや判断根拠、分析軸を追加しやすい構成とする。

## 7. 技術スタック

* **フロントエンド**: React, TypeScript, Vite, Tailwind CSS, React Router, Recharts, Axios
* **バックエンド**: Python, FastAPI, Pydantic, Mangum
* **AWS**: Lambda, API Gateway, DynamoDB, S3, CloudFront, CDK
* **データストア**: 環境変数 `STORE_BACKEND` で切替（本番: DynamoDB / ローカル開発: SQLite）

## 8. 将来拡張の方向性

* **見送り判断の検証**: 見送り後の値動きを記録し、見送り成功/機会損失/判断保留などで評価
* **銘柄情報・株価データ連携**: 銘柄名・株価の自動取得、最大含み益損の自動算出
* **分析の拡張**: 期間別・銘柄別・保有日数別成功率、リスクリワード比、期待値、連勝連敗傾向など
* **記録項目の拡張**: 地合い、業種、時価総額、決算前後、想定シナリオ・否定条件など
* **カスタマイズ**: 独自のチャートパターン・判断根拠の登録
* **認証・複数ユーザー対応**: ユーザーごとのデータ分離
* **AI支援**: 振り返りの要約、判断傾向の言語化、類似記録の提示など（売買判断は行わず、検証・振り返りの支援に限定）
